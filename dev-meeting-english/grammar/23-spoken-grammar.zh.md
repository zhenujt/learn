## 这一课解决什么问题

这是**看懂字幕的关键一课**。会议字幕和课本句子长得很不一样。比如下面这句真实字幕（已匿名）：

> Yeah, I mean, so I, I think we can, we can basically just, you know, keep it for now, right?

第一次看会觉得很乱。但去掉填充词、合并重复以后，它就是一句很简单的话：

```text
I think we can keep it for now.
我觉得我们可以先保留现状。
```

字幕里大约**三分之一的词**是 `okay`、`yeah`、`so`、`just`、`I mean` 这类"信号词"，或者是说话人重复、重说的部分。课本不教这些，所以你会觉得"每个词都认识，就是看不懂"。

**学完这一课，你应该能：**

1. 知道 10 个最常见的填充词各自在"发什么信号"，读字幕时能快速跳过或利用它们。
2. 看懂碎片句和省略句，例如 `Nothing from my side.`、`Any questions?`、`Sounds good.`。
3. 处理重复、重说和附加疑问，找到说话人"最后想说的那个版本"。
4. 认出非母语说法和语音识别（ASR）错误，并会用方法猜出原本的词。

## 1. 先建立一个正确的认识

**口语不是"说错了的书面语"。** 人在边想边说时，会自然地：

- 用填充词争取思考时间（`so`、`um`、`you know`）；
- 省掉大家都知道的部分（`Sounds good.` 省掉了 `That`）；
- 说到一半换个说法（`we can, we can…`、`is there, I mean, do we have…`）。

母语者开会也这样说话，这不是英语差的表现。你要做的是**读懂它**，而不是把每个词都翻译出来。

读一句乱的字幕，用这个顺序：

1. **删**：删掉填充词。
2. **并**：合并重复的词，保留最后一次。
3. **补**：补出省略的主语、动词。
4. **修**：改掉明显的识别错误。
5. **找**：找主干（谁 + 做什么），见 [G01](01-sentence-skeleton.zh.md)。

## 2. 填充词：每个词在发什么信号

填充词不是"没用的词"，它们告诉你说话人**下一步要干什么**。

| 词 | 频率 | 主要信号 | 读字幕时 |
| --- | --- | --- | --- |
| `okay` / `yeah` | 🔴 330 | 收到；开始；换话题 | 句首出现常表示"下一段开始了" |
| `so` | 🔴 174 | 开始说；总结；换话题（不一定是"所以"） | 句首的 `so` 多半可以跳过 |
| `just` | 🔴 47 | 刚刚 / 只是 / 让语气变软 | 看位置判断意思 |
| `I mean` | 🔴 17 | 我换个说法；我解释一下 | 后面的才是真意思 |
| `you know` | 🟡 10 | 你懂的；我在想下一个词 | 直接跳过 |
| `like` | 🔴 | 比如；大约；思考停顿 | 停顿用法直接跳过 |
| `actually` | 🟡 7 | 其实（纠正、补充新信息） | 注意：后面常有转折 |
| `kind of` / `sort of` | 🟡 7 | 有点、大概、某种 | 语气变模糊，不是"种类" |
| `basically` | 🟢 4 | 总结一下、简单说 | 后面是要点 |
| `right?` | 🟡 4.5 | 对吧？（确认） | 说话人在等你确认 |

### 2.1 okay / yeah / so：开场、收到、换话题

```text
Okay, so let's move to the platform part.
好，我们来看平台部分。（okay + so：换话题）

Yeah, thanks for sharing.
好的，谢谢分享。（yeah：收到）

So for this sprint, we will focus on the CI pipeline.
这个 Sprint 我们会重点做 CI 流水线。（句首 so：开始说，不是"所以"）

So yeah, that's all from my side.
嗯，我这边就这些。（so yeah：收尾）
```

> `yeah` 不一定是"同意"。很多时候只是"我在听"。真正同意会说 `I agree` 或 `That makes sense`。

### 2.2 just：三种意思

```text
I just merged the PR.
我刚刚合并了这个 PR。（刚刚：just + 过去时 / 完成时）

Just a quick question.
就一个小问题。（只是）

You can just raise your hand.
你直接举手就行。（软化语气，让请求听起来不那么强硬）
```

### 2.3 I mean / you know：修正和停顿

```text
We need a test plan, I mean, a simple checklist.
我们需要一个测试计划，我是说，一个简单的检查清单。（I mean：修正，以后面为准）

I mean, we have done the comparison, but have we concluded anything?
我是说，我们已经做了对比，但有结论了吗？（I mean：解释自己的意思）

It's just a spike, you know, a research task.
这只是一个 spike，你懂的，一个调研任务。（you know：停顿、找共鸣）
```

### 2.4 actually / basically / kind of / like

```text
Actually, the story is already done.
其实这个 Story 已经做完了。（actually：纠正对方的以为）

Basically, we want to reduce manual testing.
简单说，我们想减少手动测试。（basically：要点来了）

It's kind of a blocker for us.
这对我们来说算是个阻塞。（kind of：语气变模糊）

It takes like fifteen minutes.
大概要十五分钟。（like：大约）

We need, like, a shared config for all repos.
我们需要，嗯，一个所有仓库共用的配置。（like：思考停顿，可删）
```

> ⚠️ `kind of` 在这里不是"种类"。`some kind of training` 才是"某种培训"。看后面：接名词多半是"某种"，接形容词或放在句中当插入语多半是"有点"。

## 3. 碎片句和省略：主语和动词被省掉了

会议里很多句子没有主语，甚至没有动词。它们省掉的是**大家都知道的部分**：`I`、`it`、`that`、`do you`、`is`。

**公式：** 碎片句 = 完整句子 − 已知的主语 / 助动词 / be 动词

| 字幕里的碎片句 | 补全后 | 意思 |
| --- | --- | --- |
| `Nothing from my side.` | `I have nothing to update from my side.` | 我这边没有更新 |
| `Any questions?` | `Do you have any questions?` | 有问题吗？ |
| `Sounds good.` | `That sounds good.` | 听起来不错 / 可以 |
| `Got it.` | `I've got it.` | 明白了 |
| `Not yet.` | `It's not done yet.` | 还没有 |
| `Will do.` | `I will do that.` | 好的，我会做 |
| `Good to know.` | `It's good to know that.` | 知道了，挺好 |
| `Next one.` | `Let's look at the next one.` | 下一个 |
| `Ready for review.` | `It's ready for review.` | 可以评审了 |
| `Same here.` | `It's the same for me.` | 我这边也一样 |
| `Done.` | `It's done.` | 搞定了 |

```text
Nothing from my side.
我这边没有更新。

Any comments or questions?
有什么意见或问题吗？

Sounds good. Thanks, everyone.
可以，谢谢大家。

Not yet. Maybe by tomorrow.
还没有，可能明天吧。

Will do.
好，我来做。
```

**替代说法**也是一种省略：用 `so` / `not` 代替前面整句话。

```text
Is it ready for release? I think so.
能发布了吗？我觉得可以。（so = it is ready）

Will it affect the native part? I hope not.
会影响 Native 部分吗？希望不会。（not = it won't affect it）

Do we need a new ticket? I don't think so.
我们需要新建工单吗？我觉得不需要。
```

> 自己说话时，碎片句完全可以用，很自然。但在**确认分工**时要说完整：不要只说 `Okay.`，要说 `Okay, I'll update the ticket by Friday.`

### 3.1 口语省略和书面省略不一样

| | 口语省略 🔴 | 书面省略 🟢 |
| --- | --- | --- |
| 省哪里 | 句子**开头**：主语、助动词、be 动词 | 句子**中间**：和前面重复的部分 |
| 靠什么补 | 靠现场情境（大家都知道在说谁） | 靠前文（前面刚出现过） |
| 例子 | `Sounds good.`、`Any questions?` | `Ken will review the backend, and Mia the frontend.` |

```text
Ken will review the backend, and Mia the frontend.
Ken 评审后端，Mia 评审前端。（书面：第二个 will review 省掉了）

When finished, please update the ticket.
完成后请更新工单。（书面：省掉了 it is）

If necessary, we can roll back.
必要的话，我们可以回滚。（书面：省掉了 it is）

I can join the call, but Leo can't.
我能参会，但 Leo 不能。（口语和书面都常用：省掉了 join the call）
```

**记法：** 口语"砍头"，书面"去重"。会议里主要是前一种；后一种多见于文档、邮件，认得即可，更多见 [G24](24-advanced-grammar-overview.zh.md)。

## 4. 重复、重说与自我修正：取最后一个版本

字幕里每万词约有 66 次重复，例如 `we can, we can`、`the, the`。原因有三种：

| 类型 | 字幕样子 | 怎么读 |
| --- | --- | --- |
| 重复（在想） | `we can, we can basically…` | 只保留一个 |
| 重说（换结构） | `are we going to, like, is there any plan to…` | 丢掉前半截，读后面的完整结构 |
| 修正（说错了） | `on Monday, sorry, on Tuesday` | 以修正后的为准 |

常见的修正信号：`I mean`、`sorry`、`or rather`、`let me rephrase`、`no, wait`。

**原则：说话人最后说出的那个完整结构，才是他想说的。**

```text
Is there any plan to add more columns?
有没有计划加更多列？（原字幕：So, are we going to, like, is there any plan to add more columns?）

We should create a separate repo for those actions.
我们应该为这些 Action 单独建一个仓库。（原字幕：We should, we should like have a separate, create a separate repo…）

The meeting is on Tuesday.
会议在周二。（原字幕：The meeting is on Monday, sorry, on Tuesday.）
```

自己说错时，也可以大方地这样修正：

```text
Sorry, let me rephrase that.
不好意思，我换个说法。

I mean the web part, not the native part.
我是说 Web 部分，不是 Native 部分。
```

## 5. 附加疑问：right? / isn't it? / is it?

附加疑问是在句尾加一个小问句，求对方确认。

### 5.1 right?：会议里最常用 🟡

不管前面是什么句子，都可以加 `right?`，意思是"对吧？我理解得对吗？"

```text
You mean the native components, right?
你是说 Native 组件，对吧？

It's on Thursday, right?
是在周四，对吧？

So we should go with the GitHub Actions solution, right?
所以我们应该用 GitHub Actions 方案，对吗？
```

### 5.2 标准附加疑问：isn't it? / don't we? 🟢

**公式：** 前肯定 → 后否定；前否定 → 后肯定；助动词和主语跟前面一致。

| 句子 | 附加疑问 |
| --- | --- |
| `It's ready,` | `isn't it?` |
| `We need a review,` | `don't we?` |
| `You've tested it,` | `haven't you?` |
| `It won't block us,` | `will it?` |
| `They can't join,` | `can they?` |

```text
It's ready for review, isn't it?
可以评审了，是吧？

We don't need a new ticket, do we?
我们不需要新建工单，对吧？
```

会议里完整的标准附加疑问很少，认得即可。自己说用 `right?` 就够了。

### 5.3 非母语的 is it? 🟢

部分印度同事会在任何句子后面加 `is it?` 或 `no?`，不管前面的动词是什么。意思和 `right?` 一样：

| 字幕里可能听到 | 标准说法 |
| --- | --- |
| `You are joining tomorrow, is it?` | `You're joining tomorrow, aren't you?` / `…, right?` |
| `It is merged already, no?` | `It's already merged, isn't it?` / `…, right?` |

能看懂就行，自己说用 `right?`。

## 6. 缩略和弱读：gonna、wanna、kinda

口语里很多词会连读、缩短。字幕软件通常会把它们**还原成完整形式**（所以 `gonna` 在字幕里每万词只有 0.4 次，`going to` 有 8 次），但有时也会照原样显示。

| 口语形式 | 完整形式 | 例句 |
| --- | --- | --- |
| `gonna` | `going to` | `I'm gonna share my screen.` |
| `wanna` | `want to` | `Do you wanna take this one?` |
| `gotta` | `have got to`（= have to） | `We gotta fix it today.` |
| `'cause` / `cuz` | `because` | `'cause the build failed` |
| `kinda` / `sorta` | `kind of` / `sort of` | `It's kinda slow.` |
| `lemme` | `let me` | `Lemme check.` |
| `y'all` | `you all`（美国南部） | `Can y'all see my screen?` |
| `there's` + 复数 | `there are` | `There's two options.`（口语常见，书面不规范） |

```text
I'm going to share my screen.
我来共享一下屏幕。（口语常说成 gonna）

We have to fix it today because the release is tomorrow.
我们今天必须修好，因为明天要发布。（口语常说成 gotta … 'cause）
```

> 开会说 `gonna` 没问题，但**写邮件、写工单不要用**。

还有日常缩写，要能一眼认出：`I'm`、`we're`、`it's`、`that's`、`let's`、`didn't`、`won't`（= will not）、`can't`、`I'd`（= I would / I had）、`we've`。

## 7. 非母语说法：字幕原文 vs 标准说法

你的同事来自不同国家，字幕里会有大量"不标准但能懂"的说法。**看懂即可，不要模仿。**

| 字幕原文 | 标准说法 | 问题在哪 |
| --- | --- | --- |
| `regarding to the timeline` | `regarding the timeline` | `regarding` 后面不加 `to` |
| `discuss about the issue` | `discuss the issue` | `discuss` 直接接宾语 |
| `thanks for your share` | `thanks for sharing` | `share` 这里是动词 |
| `there have two demos` | `there are two demos` | there be 句型，见 [G04](04-be-and-there-be.zh.md) |
| `we have two subtask` | `we have two subtasks` | 漏了复数 |
| `we need to update document` | `we need to update the document` | 漏了冠词，见 [G02](02-nouns-articles-quantifiers.zh.md) |
| `when he back office tomorrow` | `when he's back in the office tomorrow` | 漏了 be 动词 |
| `When you ready for test, …` | `When you're ready for testing, …` | 漏 be，`test` 应为 `testing` |
| `the results shows` | `the results show` | 主谓一致 |
| `how we gonna approach for it` | `how we're going to approach it` | 漏 be；`approach` 不加 `for` |
| `I already finish it yesterday.` | `I finished it yesterday.` | 中式"已经"；有 yesterday 用过去时 |
| `It is done already, is it?` | `It's already done, right?` | 万能 `is it?` |

**关于 `already` 的过度使用：** 中文"已经"用得很多，所以中国同事常在每句里都加 `already`（字幕里每万词约 25 次）。`already` 本身没错，`It's already merged.` 很自然；但：

- 和 `yesterday`、`last week` 这类过去时间一起时，用一般过去时，`already` 通常可以不要。
- 不要和"进行中"搭配：❌ `I'm already working on it since Monday.` ✅ `I've been working on it since Monday.`

## 8. 语音识别（ASR）错误：怎么猜原来的词

字幕是机器听写的。遇到口音、专有名词、技术词，机器会换成一个**发音相近的常见词**。

| 字幕里看到 | 原本的词 | 为什么会错 |
| --- | --- | --- |
| `conference` | `Confluence` | 机器不认识产品名，换成常见词 |
| `face` | `phase` | 发音几乎一样 |
| `brands` | `branch` | 尾音相近 |
| `relief` | `release` | 口音导致 |
| `Browder` | `browser` | 口音导致 |
| `Facebook` | `feasible` | 节奏和重音相近 |
| `Spring One` / `this brand` | `Sprint 1` / `this sprint` | 尾音 t 被吞 |
| `Sigma` | `Figma` | 首音相近 |
| `surprise test` | `Cypress test` | 产品名 |
| `error DevOps` | `Azure DevOps` | 产品名 |
| `reset a ticket` | `raise a ticket` | 音近 |
| `revealed` | `reviewed` | 音近 |
| `back from POC` | `back from PTO` | 缩写容易混 |

**猜词四步法：**

1. **发现不通：** 词认识，但放在句子里不合理（`merged this to our main brands`）。
2. **读出声：** 小声读一遍，想想哪个**技术词**发音和它接近（`brands → branch`）。
3. **看搭配：** `merge to main ___` 后面最常见的是 `branch`；`ready for ___` 后面常是 `release`、`review`、`testing`。
4. **看前后文：** 同一个词往往会再出现，有时第二次识别对了。还猜不出来就先跳过，会后看文档或问同事。

```text
We already merged this to our main branch to unblock others.
我们已经把它合进主分支了，好让别人不被阻塞。（原字幕：main brands）

The doc is in the Confluence folder.
文档在 Confluence 的文件夹里。（原字幕：conference folder）

Let's move to the next phase.
我们进入下一个阶段。（原字幕：next face）
```

## 9. 真实会议例句（改编）

下面是真实字幕整理后的版本，括号里说明整理时做了什么。

```text
We're going to remap the touch libraries as a first step.
第一步我们要重新映射触控组件库。（删了 Uh；合并了 as a, as a）

Okay, I'm going to share my screen. Can you see my screen?
好，我来共享屏幕。你们能看到我的屏幕吗？（gonna 还原）

I'm not sure if we have decided how we're going to approach the website.
我不确定我们有没有定下网站要怎么做。（删了 I mean、like；补了 we're）

Okay, if there are no questions about the Sprint 1 scope, I'll give a status update.
好，如果对 Sprint 1 范围没有问题，我就来更新一下状态。（regarding to 改为 about）

It's just a spike, so we don't need to test every situation.
这只是个 spike，所以不用测所有情况。（删了两个 you know）

The two solutions are feasible for us.
这两个方案对我们来说都可行。（ASR：Facebook → feasible）
```

## 10. 字幕里怎么认

把第 1 节的五步法用在一句真实字幕上：

> Yeah, I mean, so I, I prefer to keep the, keep the third party, I mean the external delegate, in a single environment.

1. **删**：`Yeah, I mean, so` → 删。
2. **并**：`I, I` → `I`；`keep the, keep the` → `keep the`。
3. **修正**：`third party, I mean the external delegate` → 以 `external delegate` 为准。
4. **找主干**：`I prefer to keep the external delegate in a single environment.`

```text
I prefer to keep the external delegate in a single environment.
我倾向于把外部代理放在同一个环境里。
```

**快速提示：**

- 句首的 `okay / so / yeah` 一律先跳过。
- 看到 `I mean`、`sorry`，以后面为准。
- 看到 `right?`，说明对方在等确认，你可以回 `Yes, that's right.` 或 `Not exactly.`
- 看到奇怪的普通词（`face`、`conference`、`relief`），先怀疑是技术词被识别错了。

## 11. 常见错误

这些是**自己说话时**容易犯的错误：

| ❌ 错误 | ✅ 正确 | 原因 |
| --- | --- | --- |
| `Sound good.` | `Sounds good.` | 省掉的主语是 `That`，动词要加 s |
| `Any question?` | `Any questions?` | 问"有没有问题"习惯用复数 |
| `Nothing from me side.` | `Nothing from my side.` | `my side` |
| `Regarding to the release, …` | `Regarding the release, …` | 不加 `to` |
| `It's ready, is it?` | `It's ready, right?` / `isn't it?` | 附加疑问要反着来，或用 `right?` |
| 每句都用 `basically` | 只在总结要点时用 | 过多会让人觉得你在绕 |
| 邮件里写 `gonna`、`wanna` | `going to`、`want to` | 只适合口语 |
| `I already fixed it yesterday.` | `I fixed it yesterday.` | 有过去时间，`already` 多余 |

## 12. 你可以直接用的句子

```text
Nothing from my side. Thanks.
我这边没有更新，谢谢。

Sounds good to me.
我觉得可以。

Got it. I'll take a look.
明白了，我看一下。

Sorry, let me rephrase that.
不好意思，我换个说法。

I mean the web part, not the native part.
我是说 Web 部分，不是 Native 部分。

So basically, we need one more day.
简单说，我们还需要一天。

You mean the release branch, right?
你是说发布分支，对吧？

Not yet. I'll update the ticket once it's done.
还没有。做完后我会更新工单。
```

## 13. 练习

**A. 下面句子里的 `just` / `so` / `actually` / `like` 是什么意思？**

1. I **just** pushed the fix.
2. **Just** a quick update from me.
3. **So** for the native part, we are still waiting for approval.
4. **Actually**, it's not a bug. It's expected behavior.
5. The build takes **like** twenty minutes.

**B. 把碎片句补成完整句子**

1. Any updates?
2. Sounds good.
3. Not yet.
4. Will do.
5. Nothing from my side.

**C. 整理字幕，写出主干**

1. Okay, so, um, we, we have finished the, the login page already.
2. So are we going to, like, is there any plan to support iOS?
3. Yeah, I mean, regarding to the timeline, we can, we can discuss about it offline.

**D. 猜出被识别错的词**

1. Let's move to the next **face**.
2. I put the doc in our **conference** page.
3. It's ready for **relief**.
4. This solution is **Facebook** for us.
5. We merged it to the main **brands**.

<details>
<summary>答案</summary>

**A.** 1 刚刚　2 只是、仅仅　3 开始说话 / 引出话题（不是"所以"）　4 其实（纠正）　5 大约

**B.**
1. Do you have any updates?
2. That sounds good.
3. It's not done yet.（或 I haven't done it yet.）
4. I will do that.
5. I have nothing to update from my side.

**C.**
1. We have finished the login page.（我们已经完成了登录页面。）
2. Is there any plan to support iOS?（有支持 iOS 的计划吗？）
3. We can discuss the timeline offline.（时间线我们可以会后再讨论。`regarding to` 和 `discuss about` 都是非母语说法。）

**D.** 1 phase　2 Confluence　3 release　4 feasible　5 branch
