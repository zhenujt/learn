# G18 Noun Clauses

>

## What This Lesson Solves

Many meeting sentences start with a short "shell", and the real content comes after it:

```text
I'm not sure if the platform team is working on it already.

Can you check if the build is green?
```

A full sentence sits inside `I'm not sure if …` and `Can you check if …`. That inner sentence is a **noun clause**.

This is also where Chinese speakers make a classic mistake: `I don't know what is it.` The correct form is `I don't know what it is.`

**After this lesson, you can:**

1. Understand and say `I think (that) …`, and know when `that` can be dropped.
2. Use `if / whether` for yes/no content: `I'm not sure if …`, `Can you check if …`, `I wonder if …`.
3. Put a question inside a sentence with **statement word order**: `Do you know when it will be ready?`
4. Recognize clauses used as subject, complement, and appositive: `What we need is …`, `The problem is that …`, `the fact that …`.

## 1. The Right Way to Think About Noun Clauses

**A noun clause is a full sentence used in the place of a noun.** Think of it as a **box**: the main clause is outside; a complete sentence is inside.

```text
I know the answer.

I know what the answer is.
```

**Three kinds of opening words:**

| Opener | What is inside | Example |
| --- | --- | --- |
| `that` (often dropped) | a statement | `I think (that) it works.` |
| `if / whether` | a yes/no question | `I'm not sure if it works.` |
| `what / how / when / who / why / where / which` | a wh- question | `I don't know how it works.` |

**Four positions for the box:**

| Position | Example | Meeting frequency |
| --- | --- | --- |
| Object (after a verb) | `I think it's ready.` | 🔴 the vast majority |
| Complement (after `is`) | `The problem is that the API is slow.` | 🟡 |
| Subject (at the start) | `What we need is a clear owner.` | 🟡 |
| Appositive (after a noun, explaining it) | `the fact that it's free` | 🟢 |

**Key rule: inside the box, always use statement order (subject + verb). No inversion, no do / does / did.**

## 2. I think (that) …: Giving Opinions 🔴

**Pattern:** `I think / guess / believe / know / hope / mean / feel + (that) + clause`

`I think` is one of the most common openers in meetings (≈ 56 per 10k). In speech, `that` is almost always dropped:

```text
I think we can start.

I think the setup is finished now.

I guess we need a separate service account.

I hope it will be fixed by Friday.

I mean the web team should own this part.

I know Alex is going to work on the native part.
```

The same structure:

```text
Please make sure that the PR passes CI.

It seems the issue is fixed.

I'm sure it's a config issue.
```

`make sure (that) …` is very frequent (`to make sure` is one of the top four-word chunks).

### 2.1 Put the Negative Before think

```text
I don't think we need to vote.
```

Subtitles often show `I think we don't need to vote`. It is understandable and not wrong, but `I don't think …` sounds more natural.

### 2.2 I think in the Middle of a Sentence

In speech, `I think` can appear anywhere as a softener. Skip it on the first read:

```text
We need to update the branch protection rule, I think.

The deadline is, I think, October 1st.
```

### 2.3 I think that's all: This that Is a Pronoun

```text
I think that's all for today.
```

Here `that` means "that thing" and is the subject inside the box: `I think (that) [that's all for today]`. This `that` cannot be dropped.

## 3. if / whether: Yes/No Content 🔴

**Pattern:** `verb / adjective + if / whether + statement`

`if` appears about 86 times per 10k words, and **about 25 of them mean "whether", not "on condition that"**. They follow these words:

| Word before | Example |
| --- | --- |
| `not sure` | `I'm not sure if it's feasible.` |
| `check` | `Can you check if the build is green?` |
| `see` | `Let's see if anyone can pick it up.` |
| `confirm` | `I will confirm with Ken if we need it.` |
| `wonder` | `I wonder if we can use GitHub Actions.` |
| `know` | `Do you know if the runner is ready?` |
| `ask` | `Let me ask if they have a deadline.` |

```text
I'm not sure if it's feasible, but we can try.

Can you check if the build is green?

Let's see if anyone can pick it up.

I wonder if we can try the GitHub Actions runner.

Do you know if the macOS runner is for the release pipeline?
```

**`I wonder if …` is a very polite way to ask or suggest** (≈ 4 per 10k). It has no question mark, but it works as a question:

```text
I wonder if anyone has other topics.
```

### 3.1 if or whether?

In meetings `if` is usually fine. Use **only** `whether` in these cases:

```text
It depends on whether the license is approved.

Whether we need it is still unclear.

We need to decide whether or not to upgrade.
```

After a preposition, as the subject (🟢), and directly before `or not`.

### 3.2 will Is Allowed Inside the Box

```text
I'm not sure if Ken will join today.

If Ken joins today, we can ask him.
```

The first `if` means "whether", so `will` is fine. The second `if` is a condition, so no `will`; see [G20](20-adverbial-clauses.md) and [G21](21-conditionals.md).

## 4. wh- Clauses: Putting a Question Inside a Sentence ⭐ The Classic Mistake

**Pattern:** `… + question word + subject + verb …` (**statement order**, no do / does / did)

| Direct question | Inside a sentence |
| --- | --- |
| `Where is the log?` | `Do you know where the log is?` |
| `When will it be ready?` | `Do you know when it will be ready?` |
| `What does this flag do?` | `Can you explain what this flag does?` |
| `Why did the build fail?` | `I'm checking why the build failed.` |
| `How can we fix it?` | `We need to figure out how we can fix it.` |
| `Who is working on it?` | `Do you know who is working on it?` |

```text
Do you know when it will be ready?

I don't know what the root cause is.

Can you show me where the setting is?

Let me know what you think.

We need to understand which pipeline is using this feature.
```

**Three points:**

- Remove `do / does / did` and put the tense back on the verb: `What does it do?` → `what it does`.
- Move `is / will / can` back after the subject: `Where is it?` → `where it is`.
- **If the question word is the subject, the order does not change:** `Who is sharing?` → `Do you know who is sharing?`

> Native speakers sometimes say `Can you tell me what's the difference?` in casual speech, and you will see it in subtitles. When you speak or write, use `what the difference is`.

**Question word + to-infinitive** is a shorter, very common box:

```text
I don't know how to fix it.

We need to decide which tool to use.
```

## 5. Clauses as Complement and Subject 🟡

### 5.1 Complement Clauses: The problem is that …

**Pattern:** `The problem / issue / thing / idea / reason / good news + is + (that) + clause`

```text
The problem is that the API is not stable.

The good news is that most stories are completed.

The idea is that designers can catch issues early.

The question is whether we have enough time.
```

In speech, `that` is often replaced by a pause, which shows up as a comma:

```text
The thing is, we don't have a test account yet.
```

`The reason is that …` is standard. `The reason is because …` is common in speech, even among native speakers, but use `that` in writing.

### 5.2 Subject Clauses: What we need is …

**Pattern:** `What + subject + verb + is + noun / clause`

`What we need` = "the thing we need". It is the subject, and it **puts focus on what comes after `is`**:

```text
What we need is a clear owner for this task.

What I want to say is that the plan is still flexible.

What we can do now is ask the platform team for help.
```

Subject clauses with `whether` or `that` are formal and rare in meetings (🟢):

```text
Whether we need it is still unclear.
```

Speakers usually move the clause to the end and use `it` as a placeholder:

```text
It's still unclear whether we need it.

It's important that everyone updates their tickets.
```

## 6. Appositive Clauses: the fact that … 🟢

**Pattern:** `abstract noun (fact / idea / question / news / concern) + that / of whether + clause`

An appositive clause **explains the content of the noun before it**. It is more common in documents and email than in meetings:

```text
We should consider the fact that the license is not free.

There is a concern that the change may break old versions.

We discussed the question of whether we should publish each component separately.
```

**How is this different from a relative clause?** In an appositive clause, `that` only links, and the clause inside is complete. In a relative clause, `that` is the subject or object of the clause, so something is missing. See [G19 Relative Clauses](19-relative-clauses.md).

## 7. When Can that Be Dropped?

| Position | Drop it? | Example |
| --- | --- | --- |
| After `think / know / say / hope / make sure` | ✅ almost always in speech | `I think (that) it works.` |
| After `The problem is` | possible, but clearer to keep | `The problem is (that) it's slow.` |
| At the start, as subject | ❌ never | `That it works is good.` (⚪ rare) |
| After nouns like `the fact` | ❌ usually kept | `the fact that it's free` |

**Reading tip:** when `think / sure / know / mean / hope` is followed directly by "subject + verb", a `that` has been dropped and the box starts there.

## 8. Real Meeting Examples (Adapted)

From real subtitles, with recognition errors fixed and names replaced:

```text
I think in general it looks good.

I'm not sure if there's any risk if we bump the version.

I'm not sure if Mia and David are aware of the email.

I will check with Ben tomorrow to see if he has any other concerns.

We need to do a quick prototype to figure out if it's feasible.

Do you know who will be working on the native design specs?

The good news is that the SSR support story is completed.

The description says we need to confirm whether Harness provides macOS runners.

Let everybody read it and understand what we want to propose.
```

## 9. Reading Noun Clauses in Subtitles

1. **Find the shell:** `I think`, `I'm not sure if`, `check if`, `see if`, `I wonder if`, `do you know`, `let me know what`. The key content follows it.
2. **Read `if` after a shell as "whether".** Test: if you can replace it with `whether`, it means "whether".
3. **Find the subject and verb inside the box:** `Do you know when [it] [will be] ready?`
4. **Recognize, but do not copy, non-native forms:**

| Heard in subtitles | Standard form |
| --- | --- |
| `I don't know what is it.` | `I don't know what it is.` |
| `Can you check how is the performance?` | `Can you check how the performance is?` |
| `I want to see what's the next step.` | `I want to see what the next step is.` |
| `We need to discuss that whether we need it.` | `We need to discuss whether we need it.` |
| `I want to double confirm that.` | `I want to double-check that.` |
| `I think we don't need it.` | `I don't think we need it.` (more natural) |

## 10. Common Mistakes

| ❌ Wrong | ✅ Right | Reason |
| --- | --- | --- |
| `I don't know what is it.` | `I don't know what it is.` | statement order |
| `Do you know when will it be ready?` | `Do you know when it will be ready?` | statement order |
| `Can you tell me what does it mean?` | `Can you tell me what it means?` | no `does` inside |
| `I'm not sure that it works.` (meaning "whether") | `I'm not sure if it works.` | yes/no content uses `if / whether` |
| `It depends on if it's approved.` | `It depends on whether it's approved.` | `whether` after a preposition |
| `I think so that it works.` | `I think it works.` | `so` cannot be followed by a clause here |
| `What we need is we need more time.` | `What we need is more time.` | do not repeat subject and verb |

## 11. Sentences You Can Use Today

```text
I think we can close this ticket.

I don't think it's a blocker.

I'm not sure if I understand the question correctly.

Can you check if the fix is deployed?

Do you know when the design will be ready?

I wonder if we can split this story into two.

Let me know what you think.

The problem is that we don't have access yet.
```

## 12. Practice

3. Is the build green? Can you check?
4. What does this script do? Can you explain?
5. Who approved the PR? I'm not sure.

2. It depends on ___ we get the budget.
3. ___ we need is more test data.

5. We need to figure out ___ to reproduce the bug.
