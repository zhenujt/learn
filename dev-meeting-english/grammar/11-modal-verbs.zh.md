## 这一课解决什么问题

会议里，大家很少只说"做什么"，更多是在说"**能不能做、要不要做、该不该做、有多大把握**"。这些"态度"就靠情态动词表达。

例如这句站会里很常见的话：

```text
I think we don't need to wait for the final design. We can start with the web part first.
我觉得我们不用等最终设计稿，可以先从 Web 部分开始。
```

`don't need to` 是"不必"，`can` 是"可以"。如果把 `don't need to` 误解成"不能"，整句意思就反了。

**学完这一课，你应该能：**

1. 掌握情态动词的三条共同规则：后接动词原形、没有三单 `-s`、否定直接加 `not`。
2. 按意思选词：能力、许可、请求、建议、必要、推测，各用哪个词。
3. 用 `can` → `could` → `would` 三档礼貌度向同事提请求。
4. 分清 `we don't need to`（不必）和 `we mustn't`（禁止）。
5. 认出 `should have done`、`might have been` 这类"回头看过去"的说法（认得即可）。

## 1. 情态动词是什么：给动作加"态度"

情态动词本身不是动作。它放在动词前面，告诉你说话人怎么看这个动作。

**公式：** `主语 + 情态动词 + 动词原形 + 其他`

同一个动作，换一个情态动词，意思就变了：

```text
We fix the bug today.
我们今天修这个 Bug。（事实或计划）

We can fix the bug today.
我们今天能修好这个 Bug。（能力、可行）

We should fix the bug today.
我们今天应该修这个 Bug。（建议）

We need to fix the bug today.
我们今天得修这个 Bug。（必要）

We might fix the bug today.
我们今天也许会修这个 Bug。（不确定）
```

**三条铁律：**

| 规则 | ✅ 正确 | ❌ 错误 |
| --- | --- | --- |
| 后面接动词原形 | `He can join.` | `He can joins.` / `He can to join.` |
| 没有三单 `-s` | `She should check it.` | `She shoulds check it.` |
| 否定加 `not`，疑问把情态动词提前 | `We can't merge it.` / `Can we merge it?` | `We don't can merge it.` / `Do we can merge it?` |

还有一条：**两个情态动词不能连用。** 字幕里常听到 `may could`、`will can`，这是错的。要用 `be able to` 代替其中一个（见第 11 节）。

> 💡 `need to`、`have to`、`be able to`、`be supposed to` 叫"半情态动词"。意思像情态动词，但用法像普通动词：要变三单（`he needs to`、`she has to`），否定和疑问要用 `do/does/did`（`Do we need to …?`、`We don't have to …`）。

## 3. can / can't：会议第一高频

`can` 每万词出现约 146 次，比 `will` 还多。它在会议里主要有四种用法。

### 3.1 能、可以（能力或可行）

```text
We can run the Android pipeline on Linux.
我们可以在 Linux 上跑 Android 流水线。

I can't access the Confluence page.
我打不开那个 Confluence 页面。

This step can be skipped if nothing changed.
如果没有改动，这一步可以跳过。
```

### 3.2 许可：让别人开始、继续或结束

主持人最常说的就是这一类：

```text
Mia, you can go ahead.
Mia，你可以开始了。

You can stop sharing now.
你现在可以停止共享屏幕了。

If you are interested, you can stay online.
如果感兴趣，可以留在会议里。
```

### 3.3 提议：We can … = "我们可以……"

`We can …` 是会议里**最温和的建议方式**。它不像 `should` 那样有"应该"的压力，只是给出一个选项。

```text
If you want, we can do the demo tomorrow.
如果你愿意，我们可以明天做演示。

I think maybe we can skip this one.
我觉得这个也许可以先跳过。

We can leave it for now and discuss it next week.
我们可以先放一放，下周再讨论。
```

### 3.4 共享屏幕时的固定说法

```text
Can you see my screen?
你们能看到我的屏幕吗？

Yes, I can see it.
能，我看到了。

Sorry, I can't hear you. I think you're on mute.
抱歉，我听不到你，你好像静音了。
```

> ⚠️ `can` 弱读成 /kən/，`can't` 读 /kɑːnt/ 或 /kænt/。语速快时，字幕识别经常把两者弄混。看到 `can` 时要结合上下文判断：后面如果有 `but`、`because`、`yet` 之类的解释，常常其实是 `can't`。

## 4. could：更礼貌的 can，也表示"可能"

`could` 有四种用法，会议里前两种最多。

```text
Could you send me the link?
你能把链接发给我吗？（礼貌请求）

We could defer the research for Azure.
我们可以把 Azure 的调研往后放一放。（委婉建议）

It could be a cache issue.
这可能是缓存的问题。（推测，把握不大）

I couldn't access the page yesterday.
我昨天打不开那个页面。（过去的能力）
```

**注意：** 说"过去某一次**成功做成**了"，不用 `could`，要用 `was/were able to` 或直接用过去时：

```text
We were able to run the pipeline on Linux yesterday.
我们昨天成功在 Linux 上跑通了流水线。

We ran the pipeline on Linux yesterday.
我们昨天在 Linux 上跑了流水线。
```

字幕里常见非母语同事用 `could` 说现在的事实，比如 `the pipeline could run successfully`。他们想说的是"流水线现在能跑通了"。听懂即可，自己说 `The pipeline runs successfully now.` 或 `We were able to run the pipeline.`

## 5. 礼貌请求的三档

向同事提请求时，选对礼貌度很重要。中国同事常常一律用 `Can you …`，对熟人没问题，但对上级或其他团队可能显得太直接。

| 礼貌度 | 说法 | 什么时候用 |
| --- | --- | --- |
| 直接 | `Can you …?` | 熟悉的同事、很小的事 |
| 礼貌（默认） | `Could you …?` / `Could you please …?` | 大多数情况 |
| 更礼貌 | `Would you mind + -ing?` / `Would it be possible to …?` | 麻烦别人、对上级、对外部团队 |

```text
Can you check this quickly?
你能快速看一下这个吗？

Could you please post that information in the channel?
你能把那些信息发到频道里吗？

Would you mind taking a look at my PR today?
你今天方便看一下我的 PR 吗？

Would it be possible to move the meeting to Thursday?
会议能不能改到周四？
```

请求许可时，用 `Can I …?` 或 `Could I …?`；`May I …?` 很正式，会议里少见。

```text
Can I share my screen?
我可以共享屏幕吗？

Could I ask a quick question?
我可以问个小问题吗？
```

> ⚠️ 回答 `Would you mind …?` 时，同意要说 `Not at all.` 或 `Sure, no problem.`。因为 `mind` 是"介意"，说 `Yes` 反而表示"我介意"。

## 6. should：建议，也表示"按理说"

`should` 有两个意思，会议里都很常见。

### 6.1 建议：应该

```text
I think we should start with the foundation components first.
我觉得我们应该先做基础组件。

Should we create a separate story for this?
我们要不要为这个单独建一个 Story？

We shouldn't merge it before QA signs off.
QA 确认之前，我们不应该合并它。
```

`I think we should …` 和 `Should we …?` 是提建议的高频句式，语气比命令温和。

### 6.2 预期：按理说应该、应该会

这是旧教材常漏掉的用法。说话人**有把握，但不是百分之百**。

```text
It should be fine.
应该没问题。

The issue should be resolved now. We will double-check tomorrow.
问题现在应该解决了，我们明天再确认一下。

It should be ready for QA by Friday.
周五前应该可以提测。

Ben should be able to help with that.
Ben 应该能帮上忙。
```

**怎么判断是哪一种：** 主语是"我们 / 你"，后面是一个要做的动作 → 多半是建议。主语是"东西"，后面是 `be + 状态` → 多半是"按理说"。

## 7. would：委婉、客气

`would` 在会议里很少表示"将会"，多数是**让语气更客气**。

```text
I would like to share a quick update.
我想简单汇报一下。

I'd like to double-check with you.
我想跟你再确认一下。

Is there any topic you would like to discuss today?
今天有什么想讨论的话题吗？

I would say it's case by case.
我觉得要看具体情况。

That would be really helpful.
那会很有帮助。
```

- `would like to` = `want to` 的礼貌版。`I'd like to …` 是 `I would like to …` 的缩写。
- `I would say …`、`I would recommend …` 用来**软化观点**，听起来不那么绝对。
- `would` 表示假设的用法（`If we had more time, we would …`）见 [G21 条件句](21-conditionals.zh.md)。

## 8. may / might：可能，但不确定

```text
We may need to downgrade to an older version.
我们可能需要降到一个旧版本。

We might need one more day for testing.
测试可能还需要多一天。

We may not have access to it, but we can still refer to the screenshots.
我们可能没有权限，但还是可以参考截图。

I might not get a chance to verify it today.
我今天可能没机会验证。
```

- 会议里 `may` 和 `might` 基本可以互换，`might` 稍微更不确定一点。
- `May I …?` 表示许可，很正式。🟢 认得即可。
- 字幕里常见 `may could`、`might got`，这是错误说法，标准是 `might be able to`、`might be` / `might have been`（见第 13 节）。

## 9. 必须、需要：need to / have to / must

### 9.1 need to：会议里最常用的"需要" 🔴

`we need to` 在 25 场会议里出现了 171 次，是第一高频的三词组合。它语气中性，只是说"有这个必要"。

```text
We need to confirm it with the QA team.
我们需要和 QA 团队确认一下。

Do we need to create another ticket?
我们需要再建一个工单吗？

He needs to update the document.
他需要更新文档。
```

### 9.2 have to：外部原因导致"不得不" 🟡

`have to` 强调**规则、流程或客观情况**让你必须这么做。

```text
We have to use Harness anyway, so let's migrate the pipeline.
反正我们必须用 Harness，那就把流水线迁过去吧。

You just have to click "Create issue".
你只需要点"Create issue"就行。

We had to roll back the release last night.
我们昨晚不得不回滚了发布。

We will have to create a new service account.
我们得新建一个服务账号。
```

`have to` 能变时态：`had to`（过去）、`will have to`（将来）。`must` 不能，这也是口语里 `have to` 比 `must` 常用的原因。

### 9.3 must：很强的"必须" 🟢

`must` 在会议里每万词只有 1.4 次。它听起来像**规定或命令**，多出现在流程说明和文档里。

```text
Each user story must have a parent feature.
每个用户故事都必须有一个父级 Feature。

It must be a premium license, I think.
我想那一定是高级版许可证吧。（推测：一定是）
```

当面对同事说话时，用 `need to` 或 `should` 更自然。`You must …` 可能听起来像在下命令。

### 9.4 had better ⚪

会议中几乎用不到，了解即可，可以跳过。`had better`（缩写 `'d better`）表示"最好……，否则会有麻烦"，带警告语气。

```text
We'd better fix it before the release.
我们最好在发布前把它修好。
```

想提建议时，用 `should` 就够了。

## 10. we don't need to 和 we mustn't：完全不同

这是中国同事最容易出错的地方。中文"不用""不能""不要"很像，英文却差别很大。

| 说法 | 意思 | 例句 |
| --- | --- | --- |
| `don't need to` / `don't have to` | **不必**，可以不做 | `We don't need to wait for approval.` |
| `shouldn't` | **不应该**，建议别做 | `We shouldn't merge it before QA.` |
| `can't` | **不能**，不允许或做不到 | `You can't push to the main branch directly.` |
| `mustn't` / `must not` | **禁止**，绝对不能做 | `You mustn't share the token.` |

```text
We don't need to review every single PR.
我们不必每个 PR 都评审。

You don't have to join the meeting if you're busy.
如果你忙，可以不来开会。

We can't deploy on Friday because of the code freeze.
因为代码冻结，周五不能部署。

You must not commit secrets to the repo.
绝对不能把密钥提交到代码仓库。
```

> 💡 25 场会议里 `mustn't` 一次都没出现，`don't need to` 出现了 53 次。口语里表示禁止，大家更常说 `Please don't …` 或 `We can't …`。

## 11. be able to 和 be supposed to

### 11.1 be able to：can 用不了的地方用它 🟡

`can` 只有现在和过去（`could`）两种形式。下面这些情况必须用 `be able to`：

```text
We will be able to finish it next week.
我们下周能完成。（跟在 will 后面）

I haven't been able to reproduce the bug.
我一直没能复现这个 Bug。（完成时）

We might be able to reuse the old pipeline.
我们也许能复用旧的流水线。（跟在 might 后面）

I won't be able to join tomorrow's meeting.
我明天的会参加不了。
```

### 11.2 be supposed to：按约定应该，但实际可能没有 🟢

```text
The job is supposed to run every night, but it didn't run yesterday.
这个任务本该每晚运行，但昨天没跑。

Who is supposed to update the ticket status?
工单状态应该由谁来更新？
```

`be supposed to` 常常暗示"**本来应该……但是**"，听到它要留意后面可能有问题。

## 12. 推测的把握度

| 把握度 | 肯定 | 否定 |
| --- | --- | --- |
| 几乎确定 | `must be`（一定是） | `can't be`（不可能是） |
| 比较有把握 | `should be`（按理说是） | `shouldn't be` |
| 一半一半 | `may / might / could be`（可能是） | `may not / might not be` |

```text
That must be the wrong token.
那一定是用错 Token 了。

It can't be a network issue. Everything else works.
不可能是网络问题，其他都正常。

It might be related to the new SDK version.
可能跟新的 SDK 版本有关。
```

## 13. 情态动词 + have done：回头看过去 🟢

会议里不多（复盘、排查线上问题时才会出现），认得即可。

**为什么需要它：** 情态动词本身没有过去式的意思。想对**已经发生的事**表达推测或遗憾，就在后面加 `have + 过去分词`。

**公式：** `情态动词 + have + 过去分词`（口语里 `should have` 常读成 `should've`，字幕里可能写成 `should of`，那是识别错误）

| 说法 | 意思 | 语气 |
| --- | --- | --- |
| `should have done` | 本该做（但没做） | 遗憾、自我检讨 |
| `shouldn't have done` | 本不该做（但做了） | 遗憾 |
| `could have done` | 本来可以做（但没做）；也可能已经…… | 遗憾，或推测 |
| `might / may have done` | 可能已经…… | 推测，把握不大 |
| `must have done` | 一定是已经…… | 推测，很有把握 |
| `can't have done` | 不可能已经…… | 否定推测 |

```text
We should have tested it on Safari.
我们本该在 Safari 上测一下的。

I should have checked the logs earlier.
我本该早点看日志的。

We shouldn't have merged it before the QA sign-off.
QA 确认之前我们不该合并的。

We could have caught this in code review.
这个问题本来在代码评审时就能发现。

It might have been the cache.
可能是缓存导致的。

The job may have failed because of the token change.
任务失败可能是因为 Token 改了。

He must have forgotten to push the change.
他一定是忘了推送改动。

It can't have been the network. Other services were fine.
不可能是网络问题，其他服务都正常。
```

**怎么认：** 看到 `should've`、`could've`、`might've`、`must've`，或者情态动词后面紧跟 `have been` / `have + -ed`，就知道说的是**过去的事**。`should have` 和 `could have` 多半带着"但实际没有"的意思。

## 14. 真实会议例句（改编）

以下句子来自真实会议字幕，修正了识别错误，人名已替换：

```text
If the QA testing passes, we can move this phase to acceptance and release.
如果 QA 测试通过，我们就可以把这个阶段推进到验收和发布。

Okay, if there are no questions, Mia, you can go ahead with the platform team.
好，如果没有问题，Mia，你可以开始讲平台组了。

We can do some offline research on this.
这个我们可以会后再调研一下。

Could you post that information in the channel?
你能把那些信息发到频道里吗？

So we think we could defer the research for Azure.
所以我们觉得 Azure 的调研可以往后推。

We had some issues today, but the issue should be resolved now. We will double-check tomorrow.
今天遇到了一些问题，不过现在应该已经解决了，我们明天再确认。

I would recommend going with the hybrid approach.
我建议采用混合方案。

Anyone with push access should be able to merge the PR.

```

## 15. 字幕里怎么认

1. **先找情态动词，再看它后面的动词。** 后面那个动词才是真正的动作：`we might need to go through …` → 动作是 `go through`。
2. **用一个字快速归类：** `can/could` → 能；`should` → 应该 / 按理说；`need to / have to` → 得；`may/might` → 可能；`would` → 客气。
3. **`should be` + 状态，理解成"按理说"**，不是"必须"。
4. **`would` 多数不翻成"将会"**，它通常只是让语气更客气。
5. **`can` / `can't` 容易识别错**，要结合上下文。
6. **情态动词 + `have` + 过去分词 = 说过去的事。** `should have` / `could have` 通常暗示"实际没做"。
7. **非母语说法能看懂就行，不要模仿：**

| 字幕里可能听到 | 标准说法 |
| --- | --- |
| `Can let me share my screen?` | `Can I share my screen?` / `Let me share my screen.` |
| `It may could be ready for QA tomorrow.` | `It might be ready for QA tomorrow.` |
| `It might got impacted.` | `It might be impacted.` / `It might have been impacted.` |
| `I would recommend to do that.` | `I would recommend doing that.` |
| `The pipeline could run successfully.`（说现在） | `The pipeline runs successfully now.` |
| `It may be cannot be used.` | `It may not work.` / `It might not be usable.` |
| `I don't think he need to rerun those.` | `I don't think he needs to rerun them.` |
| `Must we need to …?` | `Do we need to …?` |
| `We should of tested it.` | `We should have tested it.`（`should've` 被识别错） |

## 16. 常见错误

| ❌ 错误 | ✅ 正确 | 原因 |
| --- | --- | --- |
| `He can speaks English.` | `He can speak English.` | 情态动词后接动词原形 |
| `We must to finish it.` | `We must finish it.` / `We need to finish it.` | `must` 后不加 `to`；`need` 后要加 `to` |
| `Do we can merge it?` | `Can we merge it?` | 疑问句把情态动词提前 |
| `He need to check it.` | `He needs to check it.` | `need to` 是半情态，要变三单 |
| `We will can finish it.` | `We will be able to finish it.` | 两个情态动词不能连用 |
| `You mustn't come tomorrow.`（想说"不用来"） | `You don't need to come tomorrow.` | `mustn't` 是禁止，不是不必 |
| `I would like share my screen.` | `I would like to share my screen.` | `would like` 后接 `to do` |
| `Yesterday I could fix the bug.` | `Yesterday I was able to fix the bug.` | 过去成功做成一次，用 `was able to` |

## 17. 你可以直接用的句子

## 18. 练习

**A. 判断每句中情态动词的意思**（能力/许可 / 请求 / 建议 / 必要 / 不必 / 推测）

1. Could you post the link in the channel?
2. It should be fixed in the next build.
3. We don't need to rerun the pipeline.
4. You can go ahead, Mia.
5. We might need more time for testing.
6. I think we should split this story.
7. Each story must have an owner.

**B. 选择正确的词**

1. ___ you see my screen? (Can / Must)
2. It's only a test environment, so we ___ wait for approval. (don't need to / mustn't)
3. You ___ share the admin password with anyone. (mustn't / don't need to)
4. I ___ like to share a quick update. (would / will)
5. Ben ___ be able to help with this. (should / must to)
6. We ___ run the pipeline on Linux yesterday. (were able to / could)

**C. 改错**

1. He need to update the ticket.
2. It may could be ready tomorrow.
3. We will can finish it next week.
4. Can let me share my screen?
5. I would recommend to use the hybrid approach.
6. We should tested it on Safari before the release.

<details>
<summary>答案</summary>

**A.** 1 请求　2 推测（按理说）　3 不必　4 许可　5 推测（可能）　6 建议　7 必要（规定）

**B.** 1 Can　2 don't need to　3 mustn't　4 would　5 should　6 were able to

**C.**
1. He needs to update the ticket.
2. It might be ready tomorrow.（或 It may be ready tomorrow.）
3. We will be able to finish it next week.
4. Can I share my screen?（或 Let me share my screen.）
5. I would recommend using the hybrid approach.
6. We should have tested it on Safari before the release.
