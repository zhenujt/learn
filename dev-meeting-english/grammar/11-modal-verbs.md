## What This Lesson Solves

In meetings, people rarely just say *what* happens. They say whether something is **possible, necessary, advisable, or likely**. Modal verbs carry this attitude.

A typical stand-up sentence:

```text
I think we don't need to wait for the final design. We can start with the web part first.
```

`don't need to` means "it's not necessary"; `can` means "it's possible". If you read `don't need to` as "must not", you get the opposite meaning.

**After this lesson, you can:**

1. Apply the three shared rules: base verb after a modal, no third-person `-s`, `not` directly after the modal.
2. Choose the right word for ability, permission, requests, advice, necessity, and guesses.
3. Make requests at three politeness levels: `can` → `could` → `would`.
4. Tell `we don't need to` (not necessary) from `we mustn't` (not allowed).
5. Recognize past forms such as `should have done` and `might have been` (recognize only).

## 1. What Modals Do: Add Attitude to an Action

A modal is not the action itself. It sits before the verb and shows how the speaker sees the action.

**Pattern:** `subject + modal + base verb + rest`

```text
We fix the bug today.

We can fix the bug today.

We should fix the bug today.

We need to fix the bug today.

We might fix the bug today.
```

**Three rules:**

| Rule | ✅ Right | ❌ Wrong |
| --- | --- | --- |
| Base verb after the modal | `He can join.` | `He can joins.` / `He can to join.` |
| No third-person `-s` | `She should check it.` | `She shoulds check it.` |
| Negative: add `not`; question: move the modal forward | `We can't merge it.` / `Can we merge it?` | `We don't can merge it.` / `Do we can merge it?` |

One more rule: **two modals cannot stand together.** Subtitles often show `may could` or `will can`; these are wrong. Use `be able to` for one of them (see section 11).

> 💡 `need to`, `have to`, `be able to`, and `be supposed to` are "semi-modals". They mean similar things but behave like normal verbs: `he needs to`, `she has to`, `Do we need to …?`, `We don't have to …`.

## 3. can / can't: The Most Frequent Modal

`can` appears about 146 times per 10,000 words, more often than `will`. It has four main uses in meetings.

### 3.1 Ability or Possibility

```text
We can run the Android pipeline on Linux.

I can't access the Confluence page.

This step can be skipped if nothing changed.
```

### 3.2 Permission: Letting Someone Start, Continue, or Stop

```text
Mia, you can go ahead.

You can stop sharing now.

If you are interested, you can stay online.
```

### 3.3 Offers: We can … = "One option is …"

`We can …` is the **softest way to suggest** something. It offers an option without the pressure of `should`.

```text
If you want, we can do the demo tomorrow.

I think maybe we can skip this one.

We can leave it for now and discuss it next week.
```

### 3.4 Screen Sharing

```text
Can you see my screen?

Yes, I can see it.

Sorry, I can't hear you. I think you're on mute.
```

> ⚠️ `can` is usually weak /kən/; `can't` is /kɑːnt/ or /kænt/. In fast speech, captions often confuse them. Check the context: an explanation with `but`, `because`, or `yet` often signals `can't`.

## 4. could: A Politer can, and "Possibly"

```text
Could you send me the link?

We could defer the research for Azure.

It could be a cache issue.

I couldn't access the page yesterday.
```

The four uses above are: polite request, soft suggestion, low-confidence guess, and past ability.

**Note:** for a single past success, do not use `could`. Use `was/were able to` or the past simple:

```text
We were able to run the pipeline on Linux yesterday.

We ran the pipeline on Linux yesterday.
```

Non-native colleagues often use `could` for present facts, as in `the pipeline could run successfully`. They mean "the pipeline runs successfully now". Understand it, but say `The pipeline runs successfully now.` or `We were able to run the pipeline.`

## 5. Three Levels of Polite Requests

Many Chinese speakers use `Can you …` for everything. That is fine with close teammates, but it may sound too direct with managers or other teams.

| Politeness | Form | When to use it |
| --- | --- | --- |
| Direct | `Can you …?` | close teammates, small things |
| Polite (default) | `Could you …?` / `Could you please …?` | most situations |
| More polite | `Would you mind + -ing?` / `Would it be possible to …?` | bigger favors, managers, other teams |

```text
Can you check this quickly?

Could you please post that information in the channel?

Would you mind taking a look at my PR today?

Would it be possible to move the meeting to Thursday?
```

To ask for permission, use `Can I …?` or `Could I …?`. `May I …?` is formal and rare in meetings.

```text
Can I share my screen?

Could I ask a quick question?
```

> ⚠️ To agree to `Would you mind …?`, say `Not at all.` or `Sure, no problem.` Because `mind` means "object to", answering `Yes` means "I do object".

## 6. should: Advice and Expectation

### 6.1 Advice

```text
I think we should start with the foundation components first.

Should we create a separate story for this?

We shouldn't merge it before QA signs off.
```

`I think we should …` and `Should we …?` are the most common ways to make a suggestion. They are softer than an order.

### 6.2 Expectation: "It is expected to …"

Older lessons often miss this use. The speaker is **fairly confident, but not 100% sure**.

```text
It should be fine.

The issue should be resolved now. We will double-check tomorrow.

It should be ready for QA by Friday.

Ben should be able to help with that.
```

**How to tell them apart:** a person + an action to do → usually advice. A thing + `be` + a state → usually expectation.

## 7. would: Polite and Soft

In meetings, `would` rarely means "will in the future". Usually it **makes the tone more polite**.

```text
I would like to share a quick update.

I'd like to double-check with you.

Is there any topic you would like to discuss today?

I would say it's case by case.

That would be really helpful.
```

- `would like to` is the polite form of `want to`. `I'd like to …` is short for `I would like to …`.
- `I would say …` and `I would recommend …` **soften an opinion**.
- For `would` in hypothetical sentences (`If we had more time, we would …`), see [G21 Conditionals](21-conditionals.md).

## 8. may / might: Possible but Uncertain

```text
We may need to downgrade to an older version.

We might need one more day for testing.

We may not have access to it, but we can still refer to the screenshots.

I might not get a chance to verify it today.
```

- In meetings, `may` and `might` are almost interchangeable; `might` is slightly less certain.
- `May I …?` for permission is very formal. 🟢 Recognize only.
- Subtitles often show `may could` or `might got`. The standard forms are `might be able to`, `might be`, or `might have been` (see section 13).

## 9. Necessity: need to / have to / must

### 9.1 need to: The Default "Need" 🔴

`we need to` appeared 171 times in 25 meetings; it is the most frequent three-word sequence. It is neutral: something is necessary.

```text
We need to confirm it with the QA team.

Do we need to create another ticket?

He needs to update the document.
```

### 9.2 have to: An External Reason 🟡

`have to` stresses that **a rule, a process, or the situation** requires it.

```text
We have to use Harness anyway, so let's migrate the pipeline.

You just have to click "Create issue".

We had to roll back the release last night.

We will have to create a new service account.
```

`have to` changes tense (`had to`, `will have to`); `must` cannot. That is one reason `have to` is more common in speech.

### 9.3 must: Very Strong 🟢

`must` appears only 1.4 times per 10,000 words. It sounds like **a rule or an order** and appears mostly in process docs.

```text
Each user story must have a parent feature.

It must be a premium license, I think.
```

When you talk to a colleague, `need to` or `should` sounds more natural. `You must …` can sound like a command.

### 9.4 had better ⚪

Almost never used in meetings; you can skip it. `had better` (`'d better`) means "you should, or there will be trouble". It sounds like a warning.

```text
We'd better fix it before the release.
```

To give advice, `should` is enough.

## 10. we don't need to vs we mustn't: Completely Different

| Form | Meaning | Example |
| --- | --- | --- |
| `don't need to` / `don't have to` | **not necessary** | `We don't need to wait for approval.` |
| `shouldn't` | **not advisable** | `We shouldn't merge it before QA.` |
| `can't` | **not allowed or not possible** | `You can't push to the main branch directly.` |
| `mustn't` / `must not` | **forbidden** | `You mustn't share the token.` |

```text
We don't need to review every single PR.

You don't have to join the meeting if you're busy.

We can't deploy on Friday because of the code freeze.

You must not commit secrets to the repo.
```

> 💡 In 25 meetings, `mustn't` appeared zero times; `don't need to` appeared 53 times. To forbid something in speech, people usually say `Please don't …` or `We can't …`.

## 11. be able to and be supposed to

### 11.1 be able to: Where can Doesn't Work 🟡

`can` has only two forms (`can`, `could`). Use `be able to` in these cases:

```text
We will be able to finish it next week.

I haven't been able to reproduce the bug.

We might be able to reuse the old pipeline.

I won't be able to join tomorrow's meeting.
```

### 11.2 be supposed to: Expected, but Maybe Not Happening 🟢

```text
The job is supposed to run every night, but it didn't run yesterday.

Who is supposed to update the ticket status?
```

`be supposed to` often hints "**it should … but**". When you hear it, expect a problem.

## 12. How Sure Is the Speaker?

| Certainty | Positive | Negative |
| --- | --- | --- |
| Almost certain | `must be` | `can't be` |
| Fairly sure | `should be` | `shouldn't be` |
| About 50% | `may / might / could be` | `may not / might not be` |

```text
That must be the wrong token.

It can't be a network issue. Everything else works.

It might be related to the new SDK version.
```

## 13. Modal + have done: Looking Back at the Past 🟢

This is not frequent in meetings (mainly in retrospectives and incident reviews). Recognize it.

**Why we need it:** a modal has no past form of its own meaning. To guess about or regret **something that already happened**, add `have + past participle`.

**Pattern:** `modal + have + past participle` (in speech `should have` sounds like `should've`; captions may wrongly show `should of`)

| Form | Meaning | Tone |
| --- | --- | --- |
| `should have done` | it was the right thing, but we didn't do it | regret, self-criticism |
| `shouldn't have done` | it was wrong, but we did it | regret |
| `could have done` | it was possible, but didn't happen; or: possibly happened | regret or guess |
| `might / may have done` | possibly happened | low-confidence guess |
| `must have done` | almost certainly happened | confident guess |
| `can't have done` | impossible that it happened | negative guess |

```text
We should have tested it on Safari.

I should have checked the logs earlier.

We shouldn't have merged it before the QA sign-off.

We could have caught this in code review.

It might have been the cache.

The job may have failed because of the token change.

He must have forgotten to push the change.

It can't have been the network. Other services were fine.
```

**How to recognize it:** `should've`, `could've`, `might've`, `must've`, or a modal followed by `have been` / `have + -ed` means the speaker is talking about **the past**. `should have` and `could have` usually imply "but it didn't happen".

These come from real meeting subtitles, with recognition errors fixed and names replaced:

```text
If the QA testing passes, we can move this phase to acceptance and release.

Okay, if there are no questions, Mia, you can go ahead with the platform team.

We can do some offline research on this.

Could you post that information in the channel?

I would recommend going with the hybrid approach.

I encourage everyone to join the group, but you don't need to review every single PR.

```

## 15. Reading Modals in Subtitles

1. **Find the modal, then the verb after it.** That verb is the real action: `we might need to go through …` → the action is `go through`.
2. **Sort it with one word:** `can/could` → possible; `should` → advisable / expected; `need to / have to` → necessary; `may/might` → maybe; `would` → polite.
3. **Read `should be` + a state as "expected to be"**, not "must be".
4. **`would` rarely means "will"**; it is usually just politeness.
5. **`can` and `can't` are easily confused by captions**; check the context.
6. **Modal + `have` + past participle = the past.** `should have` / `could have` usually means "but it didn't happen".
7. **Recognize, but do not copy, non-native forms:**

| Heard in subtitles | Standard form |
| --- | --- |
| `Can let me share my screen?` | `Can I share my screen?` / `Let me share my screen.` |
| `It may could be ready for QA tomorrow.` | `It might be ready for QA tomorrow.` |
| `It might got impacted.` | `It might be impacted.` / `It might have been impacted.` |
| `I would recommend to do that.` | `I would recommend doing that.` |
| `The pipeline could run successfully.` (about now) | `The pipeline runs successfully now.` |
| `It may be cannot be used.` | `It may not work.` / `It might not be usable.` |
| `I don't think he need to rerun those.` | `I don't think he needs to rerun them.` |
| `Must we need to …?` | `Do we need to …?` |
| `We should of tested it.` | `We should have tested it.` (a misheard `should've`) |

## 16. Common Mistakes

| ❌ Wrong | ✅ Right | Reason |
| --- | --- | --- |
| `He can speaks English.` | `He can speak English.` | base verb after a modal |
| `We must to finish it.` | `We must finish it.` / `We need to finish it.` | no `to` after `must`; `to` after `need` |
| `Do we can merge it?` | `Can we merge it?` | move the modal forward |
| `He need to check it.` | `He needs to check it.` | `need to` takes `-s` |
| `We will can finish it.` | `We will be able to finish it.` | no double modals |
| `You mustn't come tomorrow.` (meaning "no need") | `You don't need to come tomorrow.` | `mustn't` = forbidden |
| `I would like share my screen.` | `I would like to share my screen.` | `would like to do` |
| `Yesterday I could fix the bug.` | `Yesterday I was able to fix the bug.` | single past success |
